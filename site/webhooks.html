Webhooks · developer guide new in the next release

Your first signed event in ten minutes.

The identity server can POST a signed JSON event to your systems whenever something happens on it: a user signed in, a sign-in failed, an account was locked out, tokens were issued, an application changed. This guide gets a throwaway RequestBin URL receiving real events before you write any code. It then shows you how to check a signature, write a receiver, and manage retries and dead letters.

How it works

An event is stored before it is sent, and never slows a sign-in.

The server raises an event with one call that cannot fail and does not wait. A background writer stores it as a delivery a moment later, and a dispatcher on every instance sends it. Delivery is at least once and not ordered, so a receiver de-duplicates on webhook-id and orders by created_at when order matters.

When it works
Something happensa sign-in, a token, an app or user change
In-memory queuebounded; the request does not wait
Delivery rowstored in the endpoint's shard tables
Dispatcherclaims it, signs it, POSTs it
Your endpointany 2xx = delivered
When it does not
Timeout, 408, 429, 5xxretrying, waiting 30 s, 60 s, 120 s… (up to 1 h)
Out of attempts, or another 4xx / 3xxdead, with the exact body and the last answer
Replaya new delivery with the same webhook-id and body
Quick start · about ten minutes

See real events with RequestBin, then check the signature.

RequestBin gives you a public URL that records every request sent to it and shows each one live in your browser. You can see exactly what the identity server sends without running a server of your own. Any request inspector does the same job.

Before you start

  • An ARK identity server you can restart: your own, the repository's Ark.oAuth.Oidc.Host, or Ark.oAuth.Oidc.QuickStart (both already turn webhooks on).
  • The operator account. Only the operator can configure webhooks, because an endpoint receives who signed in and from where. If you are not the operator, ask them to create the endpoint from step 3 and send you the signing secret.
  • A test tenant and test users. Events carry email addresses and IP addresses, and a bin is a third-party service on the public internet.

  1. Turn the module on 1 min

    One line in the host's Program.cs, beside the IdP's own registration, then restart:

    builder.AddArkIdp();                    // or builder.Services.AddArkOidcServer(builder.Environment);
builder.Services.AddArkWebhooks();      // ← this line
    You'll see: a Webhooks link in the admin console's top bar, opening /{tenant}/admin/webhooks. Two small control tables (ark_wh_endpoints, ark_wh_shards) appear in the IdP's database. Nothing is sent until you create an endpoint.

  2. Get a test URL from RequestBin 1 min

    1. Open requestbin.net and choose Start Testing Now. A bin opens in your browser.
    2. Copy the bin's endpoint URL, the address that requests are sent to. RequestBin's docs give its form as https://<bin-id>.d.requestbin.net.
    3. Keep the bin's tab open. That page is the viewer: captured requests appear there live, with their headers and body.

    The endpoint is HTTPS, which the server requires for anything that is not localhost. Free bins are limited in size and expire, which is fine for a test. Check their current limits if you plan to leave one running.

  3. Create the webhook in the console 2 min

    Sign in to the console as the operator, open Webhooks, choose New webhook and fill in:

    Tenantyour test tenant. To catch your own console sign-ins, choose the operator tenant (ark_idp unless you named it otherwise).
    NameRequestBin test
    Endpoint URLthe bin's endpoint URL from step 2
    Eventstick Every event (*) while you explore. Narrow it to, say, user.* later.
    StartActive
    AuthenticationNone — signature only
    Retries, storageleave the defaults (8 attempts, Shared on main)

    Press Save.

    You'll see: the signing secret, whsec_…, shown this once. Copy it somewhere safe; step 6 needs it. If you lose it, Rotate secret issues a new one.

  4. Send a test 1 min

    Select the webhook in the Endpoints table and press Send test. It sends a webhook.test event at once and waits for the answer.

    You'll see: the console shows RequestBin's status code and how long it took. In the bin, a POST arrives with these headers and a JSON body: 
    Content-Type: application/json; charset=utf-8
User-Agent: Ark-Webhooks/<version>
webhook-id: evt_…                 ← the event: the same on every retry and replay
webhook-timestamp: 1795251600     ← when this attempt was signed (Unix seconds)
webhook-signature: v1,…           ← HMAC-SHA256, see step 6
X-Ark-Event: webhook.test
X-Ark-Delivery: dlv_…             ← this delivery; a replay gets a new one
X-Ark-Attempt: 1
X-Ark-Tenant: acme

  5. Make a real event happen 2 min

    Sign in to any application of the webhook's tenant with a test user. With the operator tenant, signing out of the console and back in is enough. Then try a wrong password once.

    You'll see, within a few seconds: user.signed_in and token.issued for the sign-in, user.signed_out for a sign-out through the app, and user.signin_failed for the wrong password. Each one is a separate POST with its own webhook-id. Back in the console, the endpoint's Delivery history lists them as delivered.

    Nothing arriving? User and tenant changes, such as user.updated and tenant.updated, are raised in the operator tenant because accounts are server-wide. Sign-ins are raised in the tenant of the application signed in to. See Troubleshooting.

  6. Check the signature 2 min

    From one captured request in the bin, copy the three webhook-* headers and the raw body. Paste them, with the signing secret, into the signature checker below. If the body has been re-formatted, the check fails, so use the bin's raw view.

    You'll see: Signature valid. You have now done by hand what your receiver will do on every request. The checker also flags the timestamp as too old once five minutes have passed. That is the replay protection a live receiver applies.

  7. Clean up 1 min

    Delete the webhook (Delete, and tick Also delete its delivery history and dead letters if you want none of it kept), or Pause it to keep it for the experiments. Delete the bin in RequestBin as well. Do not reuse a secret you pasted into a web page for a real receiver: real endpoints get their own secret when they are created.

Signature checker · runs only in this page

Check a captured request against its secret.

Signatures follow Standard Webhooks: HMAC-SHA256 over {webhook-id}.{webhook-timestamp}.{raw body}, keyed with the base64-decoded part of the secret after whsec_, sent as v1,{base64}. This checker does that with your browser's Web Crypto. Nothing you type leaves the page. Even so, use it with test secrets only.

Shown once, when the webhook was created or its secret rotated.
Exactly as sent: compact JSON, escapes such as \u0027 left as they are.

Write the receiver

Verify, de-duplicate, answer fast.

A receiver needs only these lines. Each one checks the signature on the raw bytes before it parses anything, refuses timestamps more than five minutes away, skips an event it has already handled, and answers 204 at once. Any slow work happens after the answer. The secret comes from the environment, never from a tracked file. Any Standard Webhooks library can replace the verify function. 

import base64, hashlib, hmac, os, time
from flask import Flask, abort, request

app = Flask(__name__)
SECRET = os.environ["ARK_WEBHOOK_SECRET"]   # whsec_… from the console; never in git
seen = set()                                 # in production: a table with a unique key

def verify(secret, headers, body: bytes) -> bool:
    msg_id, ts, sig = headers.get("webhook-id"), headers.get("webhook-timestamp"), headers.get("webhook-signature")
    if not (msg_id and sig and ts and ts.isdigit()) or abs(time.time() - int(ts)) > 300:
        return False
    key = base64.b64decode(secret.removeprefix("whsec_"))
    expected = base64.b64encode(hmac.new(key, f"{msg_id}.{ts}.".encode() + body, hashlib.sha256).digest()).decode()
    return any(hmac.compare_digest(expected, p[3:]) for p in sig.split() if p.startswith("v1,"))

@app.post("/ark/webhooks")
def ark_webhook():
    body = request.get_data()                # the raw bytes, before any JSON parsing
    if not verify(SECRET, request.headers, body):
        abort(401)
    event_id = request.headers["webhook-id"]
    if event_id in seen:                     # a retry or replay you already handled
        return "", 204
    seen.add(event_id)
    event = request.get_json()
    app.logger.info("%s %s %s", event["type"], event["tenant_id"], event.get("subject"))
    return "", 204                           # answer fast; queue slow work
import crypto from "node:crypto";
import express from "express";

const SECRET = process.env.ARK_WEBHOOK_SECRET;    // whsec_… from the console; never in git
const seen = new Set();                           // in production: a table with a unique key
const app = express();

function verify(secret, headers, rawBody) {
  const id = headers["webhook-id"], ts = headers["webhook-timestamp"], sig = headers["webhook-signature"];
  if (!id || !ts || !sig || !Buffer.isBuffer(rawBody)) return false;
  if (!(Math.abs(Date.now() / 1000 - Number(ts)) <= 300)) return false;   // NaN fails too
  const key = Buffer.from(secret.replace(/^whsec_/, ""), "base64");
  const expected = crypto.createHmac("sha256", key).update(`${id}.${ts}.`).update(rawBody).digest("base64");
  return sig.split(" ").some(p => p.startsWith("v1,") && p.length - 3 === expected.length &&
    crypto.timingSafeEqual(Buffer.from(p.slice(3)), Buffer.from(expected)));
}

// express.raw keeps the exact bytes; express.json() would parse them and the signature could not be checked
app.post("/ark/webhooks", express.raw({ type: "application/json" }), (req, res) => {
  if (!verify(SECRET, req.headers, req.body)) return res.sendStatus(401);
  const id = req.headers["webhook-id"];
  if (seen.has(id)) return res.sendStatus(204);   // a retry or replay you already handled
  seen.add(id);
  const event = JSON.parse(req.body.toString("utf8"));
  console.log(event.type, event.tenant_id, event.subject);
  res.sendStatus(204);                            // answer fast; queue slow work
});

app.listen(5005);

using System.Security.Cryptography;
using System.Text;
using System.Text.Json;

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();
var secret = builder.Configuration["ArkWebhookSecret"]!;   // whsec_… from user secrets / key vault
var seen = new ConcurrentDictionary<string, bool>();      // in production: a table with a unique key

app.MapPost("/ark/webhooks", async (HttpRequest req) =>
{
    using var reader = new StreamReader(req.Body, Encoding.UTF8);
    var body = await reader.ReadToEndAsync();               // the exact body, before any JSON binding
    var id = req.Headers["webhook-id"].ToString();
    if (!Verify(secret, id, req.Headers["webhook-timestamp"].ToString(), req.Headers["webhook-signature"].ToString(), body))
        return Results.Unauthorized();
    if (!seen.TryAdd(id, true)) return Results.NoContent();   // a retry or replay you already handled
    var evt = JsonDocument.Parse(body).RootElement;
    app.Logger.LogInformation("{Type} {Tenant}", evt.GetProperty("type"), evt.GetProperty("tenant_id"));
    return Results.NoContent();                             // answer fast; queue slow work

static bool Verify(string secret, string id, string timestamp, string signatureHeader, string body)
{
    if (id.Length == 0 || !long.TryParse(timestamp, out var unix) ||
        Math.Abs(DateTimeOffset.UtcNow.ToUnixTimeSeconds() - unix) > 300) return false;
    var key = Convert.FromBase64String(secret.StartsWith("whsec_") ? secret[6..] : secret);
    var expected = Convert.ToBase64String(HMACSHA256.HashData(key, Encoding.UTF8.GetBytes($"{id}.{timestamp}.{body}")));
    return signatureHeader.Split(' ').Any(p => p.StartsWith("v1,") &&
        CryptographicOperations.FixedTimeEquals(Encoding.ASCII.GetBytes(p[3..]), Encoding.ASCII.GetBytes(expected)));
}

Point the webhook at it

  • On your machine: if the identity server runs there too, http://localhost:5005/ark/webhooks is accepted as it is. Loopback addresses are always allowed over plain HTTP.
  • Anywhere else: the URL must be https://. Plain HTTP to another host is refused unless the operator sets ark_oauth_server:Webhooks:AllowInsecureHttp, which a production server should never do.
  • After changing the URL, press Send test. It shows your receiver's answer right away.

What your status code tells the server

  • 2xx delivered. Only the first 4 KB of your answer is kept, in the history.
  • 5xx 408 429, a timeout or a refused connection: retried with back-off. A Retry-After header is honoured, up to the longest wait.
  • other 4xx 3xx: never send this again. It goes to the dead-letter queue after one attempt. Redirects are not followed.
  • Answer within the endpoint's timeout (15 s by default). Slow work belongs in a queue on your side.

Delivery history

Newest first, filtered by status. Open a row to see the exact body, every attempt and the answer to each. Replay any finished delivery, or cancel one that is still waiting.

pendingstored, waiting for its first attempt
in_flightclaimed by a worker; the request is under way
retryingfailed; see Next attempt
deliveredyour endpoint answered 2xx
deadmoved to the dead-letter queue
cancelledcancelled by hand before it was sent
test_faileda Send test that did not get a 2xx (tests are never retried)

Dead letters

Each dead letter keeps the exact body, the number of attempts, the last answer and the reason it is there:

  • max_attempts: it ran out of retries.
  • non_retryable: a 4xx (other than 408 and 429) or a 3xx, so the server did not try again.
  • endpoint_disabled: it was waiting when the endpoint was disabled.

Replay selected or Replay all open sends them again as new deliveries with the same webhook-id and body. The original is kept and marked with who replayed it. Purge selected deletes them for good. Dead letters are kept for 90 days and other history for 30.

Disabled after repeated failures

Every failed attempt adds one to the endpoint's count of failures in a row, and any success resets it. At 15 (the default; 0 means never), the endpoint is disabled. New events stop being queued for it, and anything waiting moves to the dead-letter queue rather than retrying against a receiver that is down. The detail panel says why and when.

To recover: fix the receiver → Send test → Enable → Replay all open.

Authentication and storage, when you need them

  • Authentication goes on top of the signature: HTTP Basic, a static token in any header, a JWT minted for each request (HS256 shared secret, or RS256 verifiable against the tenant's JWKS), or an OAuth 2.0 access token from your own token endpoint. Up to 20 custom headers. All secrets are stored encrypted and never shown again.
  • Storage: Shared suits most endpoints. Choose Dedicated for a busy or unreliable receiver, Hashed to spread high volume over tables or databases, and Monthly for long retention. The form lists every table a plan will create before you save.
Experiments · learn failure handling in 15 minutes

Make it fail on purpose, then recover.

RequestBin shows you success. To see retries, dead letters and automatic disabling, point a second webhook at a URL that answers with the status you want. The public service httpbin.org does this: /status/503 answers 503 to any POST. Each experiment needs a real event, so sign a test user in once after saving.

Settings that make an experiment take seconds, not an hour

The default policy (8 attempts, from 30 s, doubling) takes about an hour to run out. For a lab webhook, set Events user.*, Attempts, in all 4, First retry after 5, Longest wait 60. Its retries then come about 5, 10 and 20 seconds apart, each ±20%.

The recovery drill: do it once and you will know what to do when it happens

  1. On the disabled webhook, press Edit and change the URL back to your RequestBin endpoint.
  2. Send test. It works while the endpoint is disabled, and the bin receives it.
  3. Enable. The failure count goes back to zero.
  4. Open Dead letters and press Replay all open.
  5. In the bin, compare a replayed request with the original attempt. webhook-id is the same; X-Ark-Delivery is new and X-Ark-Attempt is back to 1. That is why a receiver de-duplicates on webhook-id.
Automate · management API

Script the same steps.

Everything the console does goes through /api/oauth/v1/webhooks/…, so a pipeline can do it too. It accepts the operator's console session, or a token issued to the machine client {operator tenant}_machine with the client.register scope. Writes are POST with a JSON body. Answers are { error, code, msg, data } with a real HTTP status. 

ARK=https://idp.example.com            # the identity server's base URL
OP=ark_idp                              # the operator tenant
# ARK_MACHINE_SECRET: the machine client's secret, from your secret store (Clients → ark_idp_machine → Regenerate secret)

TOKEN=$(curl -s -X POST "$ARK/$OP/oauth2/token" -d grant_type=client_credentials \
  -d client_id="${OP}_machine" --data-urlencode client_secret="$ARK_MACHINE_SECRET" \
  -d scope=client.register | jq -r .access_token)
api() { curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" "$@"; }

# 1. create: the signing secret is in this answer and nowhere else
api "$ARK/api/oauth/v1/webhooks/upsert" -d '{
  "tenant_id": "acme", "name": "RequestBin test",
  "url": "https://<bin-id>.d.requestbin.net", "events": ["*"] }' \
  | jq '{id: .data.endpoint.id, secret: .data.signing_secret}'
WH=wh_…                                 # the id printed above

# 2. send a test and see the receiver's answer
api "$ARK/api/oauth/v1/webhooks/test" -d "{\"id\": \"$WH\"}" | jq '.data | {success, status_code, duration_ms}'

# 3. delivery history, newest first
api "$ARK/api/oauth/v1/webhooks/deliveries?endpoint_id=$WH&limit=20" | jq '.data'

# 4. after an outage: re-enable, then replay every open dead letter
api "$ARK/api/oauth/v1/webhooks/status" -d "{\"id\": \"$WH\", \"action\": \"enable\"}"
api "$ARK/api/oauth/v1/webhooks/deadletters/replay" -d "{\"endpoint_id\": \"$WH\"}"

# 5. clean up, history included
api "$ARK/api/oauth/v1/webhooks/delete" -d "{\"id\": \"$WH\", \"purge\": true}"

Every configuration change is written to the identity server's audit trail with who made it. Only the URL's host is recorded, because some receivers carry a secret in the path.

Troubleshooting

When it does not do what you expect.

SymptomCause and fix
No Webhooks link; the page or API answers 404The host does not call builder.Services.AddArkWebhooks(), or you are not signed in as the operator.
Save refused: plain http is allowed only to localhost…Use an https:// URL. RequestBin and any public receiver should have one.
Save refused: credentials do not belong in the URLRemove user:pass@ from the URL and choose HTTP Basic authentication instead.
Send test answers 301, 302 or 308Redirects are not followed. Use the final URL; check for a missing trailing slash or http instead of https.
The test arrives, real events do notThe event is not in the subscription, or it is raised in another tenant. Sign-ins use the application's tenant; user and tenant changes use the operator tenant. Also check that the endpoint is not paused or disabled, and that Webhooks:Enabled is not false.
The signature does not matchThe body was changed before it was checked. Verify the raw bytes before parsing JSON (in Express, express.raw, not express.json). Other causes: the secret was rotated, or the headers came from a different attempt (each attempt has its own timestamp and signature).
The same event arrives twiceThat is expected: delivery is at least once. De-duplicate on webhook-id.
Events arrive out of orderAlso expected. Sort on the body's created_at when order matters.
The endpoint shows disabledIt failed 15 times in a row (or the threshold you set). Follow the recovery drill.
Reference

Your host can publish its own events with IArkWebhookPublisher.Publish(tenant, "billing.order_placed", data, subject), and they reach every endpoint whose patterns match. The same envelope for every event. data depends on the type. No event carries a password, secret or token.
