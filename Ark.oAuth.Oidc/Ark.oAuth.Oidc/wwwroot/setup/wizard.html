    Let’s turn this app into an identity provider

    Nothing has been configured yet, so this app is not serving sign-ins. Over the next few steps you’ll name your organization, choose a database, create the token signing key and the first administrator. When you click Install, this same running app becomes your OAuth 2.1 / OpenID Connect server. No restart, and no appsettings to edit by hand.

      Setup code

      You’re not on the server’s own machine, so we need to confirm you can see it. The setup code is printed in the server log, and saved in setup-code.txt next to the settings.

      What you will need

      • The public address people will reach this server at, for example https://id.example.com.
      • A database. SQLite needs nothing; PostgreSQL or MySQL need a server and an account.
      • Optionally: your logos, and SMTP details if users should receive activation emails.

      Token signing key

      Every ID and access token is signed with this RSA key (RS256). Clients verify signatures with the public half, which is published at the JWKS endpoint. The private half is stored in the database only. You can rotate it later from the admin console.

      You are attaching to an existing database. It keeps the signing keys it already has, so there is nothing to do here.

      First administrator

      This account signs in to the admin console and runs everything, across every tenant. Its password is stored only as a hash in the database, never in a settings file.

      You are attaching to an existing database. No account is created and no password changes: enter the username of its administrator, which is who the console will treat as the operator.

      Users & email

      How the people you add later get their first password, and how mail leaves this server.

      The SMTP password is written to the settings file, which only this server’s account can read. In production you can set it from the environment instead: ark_oauth_server__EmailConfig__pw.

      Protocol & security

      Sensible defaults are already set; change only what you know you need.

      Automation client

      A machine client, ark_idp_machine, is created for scripts and pipelines that manage this server through its API. Give it a secret now, or later from the console.

      Review & install

      Check everything once. Install writes the settings, creates the database and signs you in.

      Where things go

      • Settings: , readable only by this server’s account, and git-ignored. Anything in it can still be overridden by environment variables.
      • Administrator password, signing key and machine secret: database only. Passwords and secrets as hashes.
      • Logos: branding/ beside the settings, served at /ark-idp/branding/.
